# Deltarune Asset Patcher — Архитектура и описание проекта

## 1. Назначение проекта

**Deltarune Asset Patcher** — модульная утилита и библиотека на C# (.NET 8), предназначенная для исследования, перевода и модификации игровых ресурсов (в первую очередь диалогов и текста) в файле `data.win` игры **Deltarune** (движок GameMaker).

Проект предоставляет:
- Автоматизированное безопасное создание резервных копий (`.bak`).
- Чтение и парсинг структур данных GameMaker через `UndertaleModLib`.
- Интеллектуальный экспорт строк в JSON с фильтрацией системного мусора (GML-скриптов, технических переменных и пустых строк).
- Быстрый регистронезависимый поиск по всем строковым ресурсам.
- Замену строк в памяти с атомарной перезаписью файла на диске.
- Два режима работы: пакетный CLI (для автоматизации и скриптов) и интерактивный REPL-шелл (`delta-mod >`).

## 2. Архитектурные принципы

Проект спроектирован с упором на расширяемость, безопасность данных и разделение ответственности:

```
┌────────────────────────────────────────────────────────┐
│                   Презентационный слой                 │
│   CLI (CommandLineHandler)  │  Будущий GUI (Avalonia)  │
└───────────────────────────┬────────────────────────────┘
                            │ использует
┌───────────────────────────▼────────────────────────────┐
│                    Сервисный слой (Core)               │
│  IProjectService (Lifecycle) │ ITextManager (Strings)  │
└───────────────────────────┬────────────────────────────┘
                            │ оперирует
┌───────────────────────────▼────────────────────────────┐
│               Модели данных и Утилиты (Core)           │
│  StringEntry │ StringSearchResult │ StringClassifier   │
│             PathUtils │ DumpOptions                    │
└───────────────────────────┬────────────────────────────┘
                            │ работает через
┌───────────────────────────▼────────────────────────────┐
│            Низкоуровневая библиотека (lib/)            │
│         UndertaleModLib.dll │ Underanalyzer.dll        │
└────────────────────────────────────────────────────────┘
```

### 2.1. Полное отделение бизнес-логики от интерфейса (GUI-Ready)
Слой `Core/` не содержит вызовов `Console.WriteLine`, `Console.ReadLine` или других привязок к терминалу. 
- Все операции возвращают типизированные модели или результаты (`StringEntry`, `StringSearchResult`).
- Сервисы предоставляют C#-события (`event EventHandler`):
  - `StringModified` — уведомляет об изменении конкретной строки (индекс, старый текст, новый текст).
  - `ProjectLoaded` — сигнализирует об успешной загрузке `data.win`.
  - `ProjectSaved` — сигнализирует о завершении сохранения файла.
- Любой графический интерфейс (на **Avalonia UI**, **WPF** или **MAUI**) может напрямую подключить `IProjectService` и `ITextManager` через Dependency Injection и привязать данные к элементам управления (`DataGrid`, `TextBox` и т.д.).

### 2.2. Кроссплатформенность (Linux + Windows)
- **Пути:** Класс `PathUtils` нормализует пути для Unix-систем (раскрытие тильды `~`) и Windows (раскрытие переменных окружения `%USERPROFILE%`, `%APPDATA%` и путей с буквами дисков `C:\`).
- **Слеши:** Работа с путями строится исключительно через `System.IO.Path`.
- **Кодировки:** Все операции чтения, записи и сериализации JSON используют строгий UTF-8 с `JavaScriptEncoder.UnsafeRelaxedJsonEscaping`, что предотвращает порчу кириллицы, японских иероглифов и специальных управляющих символов диалогов.

### 2.3. Безопасность данных и отказоустойчивость
- **Автобэкап:** Перед открытием файла на запись или чтение сервис проверяет наличие `<файл>.bak`. Если бэкап уже существует, он никогда не перезаписывается поверх, сохраняя исходную версию игры.
- **Атомарное сохранение:** Запись `data.win` производится не напрямую в рабочий файл, а во временный файл вида `data.win.tmp.<guid>`. Только после успешной сериализации через `UndertaleIO.Write` временный файл атомарно замещает оригинал (`File.Move(..., overwrite: true)`). В случае сбоя или нехватки памяти оригинальный файл не повреждается.

## 3. Описание модулей и компонентов

### 3.1. `Core/Models/`
- **`StringEntry.cs`**: Модель строки для сериализации в JSON и привязки к таблицам UI. Содержит `Id` (индекс в `data.Strings`), `Text` (содержимое) и флаг `IsTechnical`.
- **`StringSearchResult.cs`**: Модель совпадения при поиске подстроки. Содержит позицию совпадения `MatchIndex`, длину и признак технической строки.
- **`DumpOptions.cs`**: Настройки экспорта строк (фильтрация технического мусора, отступы в JSON).

### 3.2. `Core/Utils/`
- **`StringClassifier.cs`**: Анализатор строковых ресурсов. В движке GameMaker таблица строк содержит не только диалоги, но и имена переменных, функций и служебных скриптов. Классификатор отсекает:
  - Пустые строки и пробелы;
  - Имена со служебными префиксами (`gml_`, `@@`);
  - Одиночные C-идентификаторы переменных и скриптов (например, `prototype`, `ini_open`, `savedata`), пропуская в выборку диалогов фразы с пробелами, знаками препинания, переводами строк и Unicode-символами.
- **`PathUtils.cs`**: Универсальный резолвер путей для Linux, Windows и macOS.

### 3.3. `Core/Services/`
- **`ITextManager.cs` / `TextManager.cs`**:
  - `GetAllStrings(DumpOptions)` — возвращает список всех или только диалоговых строк.
  - `SearchStrings(query, caseSensitive)` — регистронезависимый поиск по содержимому всех строк.
  - `ReplaceString(id, newText, out oldText)` — замена строки по индексу в оперативной памяти.
  - `DumpStringsToJson(path, options)` — выгрузка строк в структурированный JSON.
  - Событие `StringModified`.
- **`IProjectService.cs` / `ProjectService.cs`**:
  - `Load(dataFilePath, warningCallback)` — загрузка `data.win` через `UndertaleIO.Read`.
  - `EnsureBackup(dataFilePath, out backupPath, out created)` — безопасное создание резервной копии.
  - `Save(targetFilePath)` — безопасное атомарное сохранение через `UndertaleIO.Write`.
  - Свойства `IsLoaded`, `IsDirty`, события `ProjectLoaded` и `ProjectSaved`.

### 3.4. `Cli/` и точка входа
- **`CommandLineHandler.cs`**: Маршрутизирует аргументы командной строки или запускает цикл REPL, форматирует вывод в консоли (цветовая подсветка, экранирование спецсимволов при выводе).
- **`Program.cs`**: Конфигурирует консоль на UTF-8, инстанциирует сервисы и передает управление в обработчик.

## 5. Использование и примеры команд

### 5.1. Пакетный режим CLI

```bash
# Дамп только диалогов и пользовательских строк в JSON
dotnet run -- dump-strings dialogues.json

# Полный дамп всех строк файла (включая технические идентификаторы)
dotnet run -- dump-strings all_strings.json --all

# Поиск подстроки по всей игре
dotnet run -- search-strings "chapter"

# Замена диалоговой строки по ее ID с немедленным сохранением в data.win
dotnet run -- replace-string 837 "Хотите начать с Главы 1?\n[Да] / [Нет]"

# Указание произвольного пути к data.win
dotnet run -- /home/user/games/deltarune/data.win search-strings "Kris"
```

### 5.2. Интерактивный REPL-режим

При запуске без аргументов команды:
```bash
dotnet run
```
Открывается сессия моддинга:
```text
delta-mod > info
delta-mod > search "start from"
delta-mod > replace 837 "Новый текст диалога"
delta-mod > dump exported.json
delta-mod > exit
```
